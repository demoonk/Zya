# zя — автопереключатель раскладки на Rust

Автоопределение «не той» раскладки (RU ↔ EN) на уровне системного клавиатурного
хука: если слово набрано в неправильной раскладке, оно исправляется на лету,
а раскладка переключается.

## Как это работает

1. `SetWindowsHookExW(WH_KEYBOARD_LL, …)` — глобальный хук, видит все keystrokes
   системы.
2. **Раскладка отслеживается внутри хука.** `GetKeyboardLayout()` для
   foreground-окна в современных приложениях (Notepad 11) возвращается
   *устаревшим* — после реального Alt+Shift всё ещё даёт 0409, хотя клавиши
   уже дают кириллицу. Поэтому хук держит своё состояние `App::lang`:
   «посеянное» значение берётся из ОС при смене foreground-окна, а дальше
   каждый Alt+Shift (и каждое собственное переключение) флажит его. Символ
   считается через `ToUnicodeEx` именно с этой раскладкой.
3. Буквы (и «двойные» ключи `, . ; ' [ ] `) накапливаются в буфере слова.
   Неоднозначные ключи перебираются: `,` — это и запятая, и `б`. Ключ,
   оставленный пунктуацией *внутри* слова, штрафуются сильнее (18), чем на
   границе слова (4) — «привет,» остаётся «привет,», а «c]tkf» читается как
   «съела», а не «с]ела».
4. На границе слова (пробел, Enter, пунктуация) движок сравнивает две гипотезы:
   * слово как есть — оценка по словарю его алфавита;
   * зеркальное слово (RU↔EN) — оценка по словарю другого языка, с перебором
     вариантов для неоднозначных ключей.
5. Если зеркальная гипотеза уверенно лучше — одна пачка `SendInput`:
   N backspace + ретайп исправленного слова + Alt+Shift (переключение раскладки).
   Граничный ключ («` `"», `,`, `.`) дописывается той же пачкой, чтобы после
   переключения раскладки не появился лишний символ.

Языковая модель: частотные unigram/bigram/trigram (Laplace) + словарь top-50000
слов для каждого языка, нормализация по длине слова (`baseline[len]`).

### Пунктуация, набранная «не в той» раскладке

Клавиши `,` `.` `;` на ЙЦУКЕН дают `б` `ю` `ж`. Если после русского слова стоит
`б`, а запятой нет — значит это запятая, а не опечатка:

* `фактб` → `факт,`, `сказкаж` → `сказка;`, `проектЖ` → `проект:`;
* одиночные `б` `ю` `ж` сами по себе — `,` `.` `;` (русских слов из одной такой
  буквы не бывает);
* рядом с цифрами: `6б1` → `6,1`, `53ю` → `53.`, `1000ж` → `1000;`.

Правило срабатывает, только если основа слова читается по-русски (скорость
`score(head) ≥ -20`) и либо есть в словаре, либо последняя буква физически не
может стоять в русском слове на этом месте (биграмы `хб`, `йб`, `гб` в корпусе
нет). Настоящие слова на этих буквах — `клуб`, `чиж`, `багаж`, `машину`,
`батарею`, `тройную`, `веб`, `муж` — не трогаются. Такие исправления **не**
переключают раскладку (`flip: false`): клавиатура остаётся русской.

Одиночная латинская `b` — это союз `и` (та же клавиша), но только когда перед
ней было полноценное слово: `P30 b P40` → `P30 и P40`. В перечислении вариантов
`a b c d`, `Wi-Fi a b g n ac ax` предыдущий токен один символ — там `b`
остаётся `b`.

### Смешанный токен: термин и русское слово через дефис

Дефис не является разделителем слова, поэтому `OLED-дисплей`, набранный при
русской раскладке, приходит целиком как `ЩДУВ-дисплей` — ни термин, ни слово.
Токен разбивается по дефисам, и зеркало применяется только к частям, которые
состоят из кириллицы (цифры разрешены: `ввк4` = `ddr4`), отсутствуют в русском
словаре и совпадают с термином из `tech.json`:

* `ЩДУВ-дисплей` → `OLED-дисплей`, `ввк4-карта` → `ddr4-карта`;
* `мини-плеер`, `две-комнатный`, `Full-HD`, `wi-fi` не трогаются;
* раскладка не переключается: половина слова и правда набрана в другой.

### Технический словарь (exact match)

Отдельный список `data/tech.json` (318 терминов, собран из 10 статей 3dnews.ru и
10 статей ixbt.com) проверяется **до** всех эвристик: если зеркало tokens —
термин из списка, слово исправляется независимо от «правдоподобия» и от защиты
кода. Поэтому `ввк4` → `ddr4`, `щдув` → `oled`, `тмьу` → `nvme`, `ь2` → `m2`,
`1080з` → `1080p`, `5060кеч` → `5060rtx` работают даже с цифрами внутри. И
наоборот: уже набранное `ddr4`, `NVMe`, `rtx5060` остаётся как набрано.
Зеркало, которое само является русским словом (`ли` ↔ `kb`), не трогается.

Слова из тех-списка одновременно добавляются в языковую модель (вес ×30):
`data/tech_terms.txt` → EN, `data/tech_ru_terms.txt` (термины, встречающиеся в
статьях в кириллической форме) → RU.

Пересобрать статистику с нуля:

```
python tools/fetch_articles.py     # 10 статей 3dnews.ru + 10 статей ixbt.com → data/articles
python tools/build_tech.py         # → abrakadabra/data/tech.json (+ tech_terms.txt, tech_ru_terms.txt)
python tools/build_data.py         # → abrakadabra/data/lang.json (частотная модель)
python tools/tech_report.py        # → data/tech_stats.txt (частоты и зеркальные написания)
python tools/check_collisions.py   # спорные пары «русское слово ↔ тех-термин»
cargo build --release && zя techtest && zя corpus
```

## Хоткеи в режиме `run`

| Ключ | Действие |
|---|---|
| `Alt` (без Ctrl) | отменить последнее исправление (undo) |
| `Break` | сменить раскладку выделенного текста; если выделения нет — последнего слова до пробела/разделителя (дефис входит в слово: `wi-fi`) |
| `Ctrl+Break` | перевести выделенный текст в верхний регистр |
| `Shift+Break` | поменять регистр выделения на противоположный |
| `Ctrl+Alt+P` | включить/выключить автопереключение (дублируется левым кликом по значку в трее) |

Все хоткеи настраиваются в окне «Настройки» (клик по строке в таблице — нажать
новую комбинацию, `Esc` или «Отмена» — закрыть, «Сбросить» — вернуть стандартные)
или прямо в `config.json` (`hotkey_undo`, `hotkey_toggle`, `hotkey_last`,
`hotkey_selection`, `hotkey_upper`, `hotkey_invert`):
`"alt"`, `"break"`, `"f2"`, `"ctrl+alt+p"`, `"win+space"`. `break` и `pause` —
одна и та же клавиша, поэтому переключатель по умолчанию уехал на `Ctrl+Alt+P`.
Неизвестное имя возвращает значение по умолчанию.

Окно не принимает комбинации, которые заняты: `alt` сам по себе (Windows
переключает им раскладку), одиночные `ctrl`, `shift` или `win` (нужна ещё
обычная клавиша), `break` на строках, где он не стоит по умолчанию (он занят
undo/последним исправлением), и системные `ctrl+alt+delete`, `win+l`, `win+r`,
`win+e`, `win+i`, `win+a`, `win+tab`, `alt+f4`, `alt+tab`, `ctrl+shift+esc`.

`Alt` считается «одиноким» только если между нажатием и отпусканием не было
другого ключа: `Alt+3`, `Alt+F4` и другие shortcuts не вызывают undo. То же
касается `Alt+Shift+<key>` — такой аккорд не считается сменой раскладки.

## Значок в трее

Значок показывает текущую раскладку: `RU` — русская, `EN` — английская. Буквы
рисуются на прозрачном фоне без подложки: белые в тёмной теме, чёрные в светлой
(тема берётся из `AppsUseLightTheme`, вручную её можно задать переменной
`ZYA_THEME`). Когда автоисправление выключено, поверх букв идёт красный косой
штрих. Иконка приложения (`data/app.ico`, 256/128/64/32/16 px) — клавиша-кейкап с
чёрной `Z` и красной `Я`, вшивается в exe через `build.rs`.

* левый клик — включить/выключить автоисправление;
* правый клик — меню: «Автосправление раскладки», «Автозапуск при входе»,
  «Настройки», «Выход».

«Настройки» открывает окно с тремя вкладками слева:

* **Настройки** — версия, «Проверить обновления» (становится «Обновить», когда на
  GitHub есть более свежий релиз с asset `z.exe`), «Автозапуск при входе»,
  «Запускать как администратор» и таблица горячих клавиш;
* **Игнорировать** — «Добавить из запущенных», «Добавить новый процесс»,
  «Удалить выбранное», фильтр и список исключённых процессов и папок; правая
  кнопка мыши на строке — «Скопировать строку», «Скопировать весь список»,
  «Удалить»;
* **Лог** — цветные строки из `diario.log`, фильтр, «Обновить», «Очистить» и
  копирование по правой кнопке мыши.

## Исключения

* `exclude_processes` — подстрока имени exe или заголовка окна (`cmd.exe`,
  `terminal`, `password`, `пароль` …);
* `exclude_dirs` — папка, из которой запущена программа: если путь exe начинается
  с одного из этих префиксов, автоисправление в этом процессе отключается
  (например `"c:\\games"`).

## Автозапуск

`autostart: true` в `config.json` (или пункт меню в трее, или
`zя autostart on`) регистрирует `HKCU\…\CurrentVersion\Run\zя.exe`
и запускает приложение скрыто (`run headless` — консольное окно прячется,
остаётся только RU/EN значок в трее). Если включено «Запускать как
администратор», вместо Run-записи создаётся задание `ZyaAutoStart` в
Планировщике заданий (`/sc ONLOGON /rl HIGHEST`). `zя install` копирует
бинарник в `%APPDATA%\zя\zя.exe` и включает автозапуск.

## Конфигурация

`%APPDATA%\zя\config.json`:

```json
{
  "margin_unknown": 2.5,
  "margin_known": 1.0,
  "word_bonus": 20.0,
  "plausibility": -12.0,
  "min_len": 3,
  "protect_code": true,
  "hotkey_undo": "alt",
  "hotkey_toggle": "ctrl+alt+p",
  "hotkey_last": "break",
  "hotkey_selection": "break",
  "hotkey_upper": "ctrl+break",
  "hotkey_invert": "shift+break",
  "whitelist": ["ok", "git", "vim", "cd", "js", "sudo", "bash", "cmd", "ctrl", "alt", "shift", "enter", "http", "https", "www", "com", "org", "ru", "net", "rust", "python", "php", "sql", "html", "json", "url", "pdf", "exe", "dll", "file"],
  "exclude_processes": ["cmd.exe", "powershell", "conhost", "terminal", "password", "пароль"],
  "exclude_dirs": ["c:\\games"],
  "auto_enabled": true,
  "autostart": false,
  "log_enabled": true
}
```

* `margin_unknown` — запас вероятности, нужный, чтобы переписать слово, зеркальная
  форма которого **не** в словаре.
* `margin_known` — запас, если зеркальная форма — известное слово.
* `min_len` — слова короче этого не трогаем.
* `plausibility` — нижняя граница «похожести» зеркальной формы на слово этого
  языка (в log-вероятностях относительно среднего реального слова той же
  длины). `-12` отсеивает случайные нажатия вроде `bqk`/`фыв`, но не мешает
  нормальным словам.
* `protect_code` — не трогать токены, похожие на код: с цифрами, `_ / \ : @ #`,
  расширениями (`.txt`, `.com`, `.pdf` …), `http`/`www.` и со строчной буквой
  после заглавной (camelCase). В хуке это работает и на уровне набора: как только
  в слове появляется цифра или разделитель, всё до пробела считается идентификатором.
* `whitelist` / `exclude_processes` — не трогать эти слова и эти процессы
  (подстроки имени exe или заголовка окна).

Журнал переключений: `%APPDATA%\zя\diario.log`.

## Как хук работает в Telegram Desktop

Telegram Desktop — это Qt, у него нет Win32 `EDIT`-окна, поэтому стандартные
приёмы (`GetWindowText` поля ввода, `ES_PASSWORD`, child-окна) там не работают.
Тем не менее `WH_KEYBOARD_LL` глобален: keystrokes, которые Qt получает через
`WM_KEYDOWN`, видны хуку точно так же, как в классических окнах. Проверено:

* хук видит нажатия в composer Telegram (`raw code=0 vk=… scan=…` в verbose-логе);
* `ToUnicodeEx` с отслеживаемой раскладкой даёт правильный символ (в том числе
  заглавную `T` при Shift — в injected-событиях `GetAsyncKeyState` внутри хука
  не надёжен, поэтому регистр нормализуется по отслеживаемому Shift);
* исправление выполняется той же пачкой `SendInput` (backspace + ретайп +
  Alt+Shift) и Qt принимает её корректно;
* раскладка в Qt-окне определяется через thread of window
  (`GetKeyboardLayout(GetWindowThreadProcessId(hwnd))`) — для главного окна
  Telegram это работает, а переключение Alt+Shift хук отслеживает сам.

Для проверки использовался только чат **«Избранное» (Saved Messages)**: текст
набирался в composer, читался обратно через Ctrl+A → Ctrl+C → clipboard
(`CF_UNICODETEXT`), затем composer очищался. Ни одно сообщение не было
отправлено.

`zя tgtest` (11 проверок, все зелёные):

1. EN-раскладка, «ghbdtn» → «привет» (хук сработал в Qt);
2. раскладка реально переключилась: «vbh» → «мир»;
3. хоткей отмены (по умолчанию Alt) вернул «ghbdtn»;
4. `ghbdtn.com`, `ghbdtn123`, `my_file`, `ghbdTn` не тронуты (защита кода);
5. правильный русский («привет проверка») не переписывается;
6. обратное направление: RU-раскладка, «hello» → «hello»;
7. хоткей toggle (`Ctrl+Alt+P` по умолчанию) выключает авторежим — «ghbdtn» остаётся «ghbdtn»;
8. включение работает;
9. тех-термины в RU-раскладке: «ввк4 тмью щдув» → «ddr4 nvme oled»;
10. после теста composer пуст (ничего не отправлено).

Важная деталь: хоткеи **перехватываются полностью** (`LRESULT(1)`), чтобы
`Ctrl+Alt+U`/`Pause` не «просачивались» в поле ввода приложения.

(`Sim::press` → символ по раскладке → токен → `Engine::decide_with`), без окон и
без `SendInput`. `wintest`, `article` и `tgtest` нужны только как проверка
совместимости: что пачка `SendInput` действительно работает в EDIT-окне и в Qt.

* `selftest`: 13/13;

## Ограничения (текущие)

* Обрабатываются только RU (0x0419) и EN (0x0409); другие раскладки пропускаются.
* Раскладка отслеживается внутри хука (см. пункт 2 выше). Если пользователь
  меняет язык не через Alt+Shift (языковая панель, Win+Space), состояние может
  разойтись — при смене foreground-окна хук снова читает значение из ОС.
* ~0.4 % пропусков в round-trip тесте, в основном на ключах `, . ; ' [ ] `,
  которые в другой раскладке дают буквы `б ю ж э х ъ` (например `ruk` и `рук`
  неразличимы — обе формы существующие слова).
* Токен обрабатывается только когда закрыт разделителем: слово остаётся как
  набрано, пока не нажат пробел, Enter или пунктуация. В симуляции статьи
  границы добавляются искусственно.
* Латинские аббревиатуры, набранные уже после автоматической смены раскладки
  (`YT`, `VK` в русской раскладке дают `НЕ`, `МЛ`), обратно не переводятся:
  движок исправляет только латинские токены, а не кириллические.
* Поля ввода пароля не трогаются: `ES_PASSWORD` (0x0010) совпадает с `WS_CHILD`,
  поэтому стиль окна не подходит — хук смотрит на имя/заголовок окна (login,
  password, пароль, вход) и на `exclude_processes` из конфига.
* Автозапуск: `zя autostart on` пишет значение `zя.exe` в `Run` (HKCU),
  `autostart off` убирает его. Если включено «Запускать как администратор»,
  вместо Run-записи создаётся задание `ZyaAutoStart` в Планировщике
  (`/sc ONLOGON /rl HIGHEST`).
* Две копии движка в памяти невозможны: при запуске `run` создаётся мьютекс
  `Global\ZyaLayoutGuard`, вторая копия сразу выходит — это защита от двойных
  переключений, когда старый `zя.exe` не был убит.
* При первом запуске настройки и журнал автоматически переносятся из старой
  папки `%APPDATA%\AbraKadabra` в `%APPDATA%\zя`.

## Сборка

```
cargo build --release          # stable-x86_64-pc-windows-gnu
cargo test
```

Имя пакета — `zya`: MinGW `ld` не может создать исполняемый файл с кириллицей
в имени, поэтому бинари называются `z_single_app` и `z_single_launcher`.
Релизный `z.exe` собирает `tools\build.ps1`:

```
powershell tools\build.ps1     # z_app.exe -> tools\z.bin -> target\release\z.exe
```

`z_single_app` (манифест `asInvoker`) — само приложение, его бинарь кладётся в
`tools\z.bin`; `z_single_launcher` (`requireAdministrator`) — установщик `z.exe`
с иконкой и манифестом, он копируется в `release\z.exe`.
